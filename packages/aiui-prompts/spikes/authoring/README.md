# Prompt authoring syntax bench

This private, unpublished package is an executable **API experiment**, kept in source control so
we can compare iterations. It is not the production `aiui-prompts` implementation. The tiny owned
JSX runtime and compiler have no runtime dependencies on existing aiui packages, React, Solid,
or another prompt framework. The adjacent [viewer spike](../inspector/README.md) uses its own fixtures;
it does not import this compiler.

The main workflow is **build one document → compile its content → render one current turn → attach
history**. A document is not intrinsically a message, and a current turn is not a conversation.
A provider adapter would subsequently lower the prepared envelope to a specific API payload.
That adapter is not implemented; none of these operations fetches an asset or calls a model.

Run from the repository root:

```sh
pnpm --filter @habemus-papadum/aiui-prompts-authoring-spike dev
pnpm --filter @habemus-papadum/aiui-prompts-authoring-spike examples
pnpm --filter @habemus-papadum/aiui-prompts-authoring-spike examples --json
pnpm --filter @habemus-papadum/aiui-prompts-authoring-spike examples:check
pnpm --filter @habemus-papadum/aiui-prompts-authoring-spike typecheck
pnpm --filter @habemus-papadum/aiui-prompts-authoring-spike test
```

The browser playground is at <http://127.0.0.1:5218>. Pick one of the seven examples and move
through **Compose → Compile → Current turn → Attach history**, keeping the real TSX source and
the current invocation alongside the outputs. The name, conditional paragraph, background
selection, revision, and history controls execute the actual library; they do not load the saved
JSON artifacts. Each stage has a readable view, expandable structures, and complete JSON to copy.

The source pane is read-only; edit the example files for arbitrary code changes. Examples that
return only compiled results cannot show discarded input nodes, so the composition view labels
their retained definitions explicitly. The playground adds `renderTurn` and `prepareRequest` to
content-only examples, as shown in the invocation pane. The multi-message example exposes each
compiled contribution separately. Asset fixtures contain descriptors only; no image bytes are
invented or fetched. The separate inspector still owns the mocked Markdown/math preview experiment.

`build:playground` builds the site into `dist/playground`, independently of the library build.
The playground uses aiui-design's static CSS/font assets as a development dependency; none of the
prompt runtime, JSX implementation, or exported library modules imports it or another aiui runtime.

The `examples` command executes every example and lists its stages. `--json` prints the actual
results. The checked-in [`expected/`](expected/) artifacts were generated by executing these
examples. `examples:check` compares their data with a fresh execution; `examples:write` deliberately
updates them after a reviewed syntax change. These are inspectable expectations, not hand-written
claims about unimplemented behavior.

## Start with one prompt

```tsx
import {
  Prompt, Paragraph, Text, compilePrompt, renderTurn, prepareRequest,
} from "@habemus-papadum/aiui-prompts-authoring-spike";

function greeting(name: string) {
  return (
    <Prompt>
      <Paragraph>Hello, <Text value={name} source={{ label: "name argument" }} />!</Paragraph>
      <Paragraph>Keep your answer concise.</Paragraph>
    </Prompt>
  );
}

const document = greeting("Ada");
const compiled = compilePrompt(document);
const turn = renderTurn({ input: compiled });
const prepared = prepareRequest(turn);
```

The important output shapes are:

```ts
// document: immutable evaluated composition; application code has already run.
{ kind: "prompt", children: [/* paragraph nodes and their text children */] }

// compiled: serializable semantic definitions, contextual occurrences, parts and maps.
{
  schema: "authoring-spike/1",
  definitions: [/* each evaluated node once, linked by IDs */],
  occurrences: [/* each placement, including parent and resolved heading depth */],
  selection: {},
  parts: [{ type: "text", text: "Hello, Ada!\n\nKeep your answer concise." }],
  outputMap: [/* exact occurrence → part-local UTF-16 output intervals */],
  metrics: { textCodeUnits: 38, images: 0, tokenCount: null },
}

// turn: current-only messages, each retaining its compiled prompt for inspection.
{ messages: [{ role: "user", prompt: compiled }] }

// prepared: neutral inspection envelope; this is NOT any provider's wire format.
{
  schema: "request-envelope-spike/1",
  status: "prepared-not-sent",
  current: {
    messages: [{ role: "user", parts: compiled.parts }],
  },
  history: { kind: "none" },
  accounting: { currentTextCodeUnits: 38, history: "none", requestTokens: null },
}
```

Use [example 01](src/examples/01-greeting.prompt.tsx) and its
[full output](expected/01-greeting.json) for the concrete, non-elided artifact.
The compiler coalesces adjacent text without discarding contribution boundaries. Source metadata
is manually supplied ownership, not compiler-captured file/line spans. `explainRange()` reports
those owners; unavailable sources stay unavailable.

## Compose reusable content; resolve headings where it is placed

```tsx
const evidence = (
  <Section title="Evidence">
    <Paragraph>The observed value is 4.500 eV.</Paragraph>
  </Section>
);
const document = (
  <Prompt>
    {evidence}
    <Section title="Independent check">{evidence}</Section>
  </Prompt>
);
```

Compilation emits `# Evidence` for the first placement and `## Evidence` for the second.
One definition has two occurrence IDs; the fragment never gains a mutable parent. Helper function
nesting has no influence on headings. Markdown depths above six fail explicitly in this spike.

Each component is a normal synchronous TypeScript function returning a prompt node. Use arrays,
loops, conditionals, imports and helper functions. Await data before building the prompt; promises
are rejected as children. Compilation never reruns application functions. Omission uses `null` or
`false`; an explicitly supplied `undefined` child is rejected.

`Prompt` and `Section` separate children by blank lines. `Paragraph`, `Group` and `<>...</>`
concatenate children. `Join` inserts an explicit separator between nonempty children. This makes
paragraph and table boundaries visible in the authoring code. It also exposes a design question:
a flat array under `Prompt` becomes separately spaced blocks, while the same array under `Paragraph`
is inline content. We should evaluate this convention before freezing an API.

## Preserve scientific content and media order

```tsx
const energy = "4.500"; // lexical precision belongs to the value, not a JS number
const equation = tex`\hat{H}\,\psi(r) = E\,\psi(r)`;
const document = (
  <Prompt>
    <Paragraph>The measured energy is {energy} eV.</Paragraph>
    <Math value={equation} />
    <Paragraph>Inspect this curve:</Paragraph>
    <Image asset={preparedAsset} />
    <Paragraph>Explain how the curve relates to the measured energy.</Paragraph>
  </Prompt>
);
```

The result contains **text, image, text**, in that order. Images never become placeholder strings
in the payload. Asset descriptors carry identity, revision, MIME type, dimensions and a host-owned
URI; this bench performs no fetching, hashing, upload or provider capability negotiation.
The scientific example uses a `fixture:` SVG descriptor, not a promise that an LLM accepts SVG.

`Math` emits exact string-valued TeX inside inline or display delimiters (`display={false}` means
inline). Preview rendering is separate and cannot rewrite that string. The bench preserves
backslashes, `aligned`, Unicode units and precision strings; it does not parse TeX, infer scientific
meaning, handle macro dependencies or perform algebra.

`Xml` produces escaped, namespace-free XML elements. Names and the XML character repertoire are
validated; nested XML elements stay structural. Attributes escape quotes and whitespace as well as
ampersands/angle brackets. Only text, groups, joins, choices and nested XML are accepted inside XML.
A complete prompt may contain several XML snippets; no single-root XML document format is claimed.

Normal JSX has important text rules: prose line breaks/indentation normalize before our runtime
receives children, and entities such as `&amp;` decode. `separator="\n"` is a literal backslash and
letter n; use `separator={"\n"}` for a newline. Exact code, TeX, CRLF or leading spaces belong in
`<Text value={preparedString} />` or `<Math value={tex`...`} />`. There is no implicit dedent.
Strings from a file preserve their contents; a source literal is subject to JavaScript's rules.

## Select current content; keep history separate

```tsx
const document = (
  <Prompt>
    <Paragraph>Explain the new spectrum.</Paragraph>
    <Choice name="background" short={<Paragraph>Use the previous model.</Paragraph>}>
      <Section title="Background">{fullExplanation}</Section>
    </Choice>
  </Prompt>
);
const compiled = compilePrompt(document, { selection: { background: "omit" } });
const turn = renderTurn({ input: compiled, instructions: compiledInstructions });
const prepared = prepareRequest(turn, { history });
```

`Choice` is an authored full/short/omit experiment, not an automatic optimizer. Selection names
are artifact-global and unknown names fail. All definitions remain in the artifact; an omitted
choice retains its occurrence/decision but has no output range or descendant placements. Empty
sections and unused separators disappear during emission. The original document is unchanged.
There is no token budget estimate: UTF-16 code-unit counts are explicitly not tokens.

Four history forms are intentionally distinct:

| History | Meaning in the prepared envelope |
| --- | --- |
| `{ kind: "none" }` | No explicit or remote history supplied. |
| `{ kind: "messages", messages }` | Immutable replay of the bench's neutral user/assistant messages and ordered parts. This is only a simple conversational subset. |
| `{ kind: "provider-items", protocol, items }` | Opaque JSON replay items, preserving order, tool-call IDs and provider-specific structure. The bench does not validate their protocol. |
| `{ kind: "remote", provider, reference: { kind, id } }` | Opaque conversation, thread or previous-response reference. No history messages are fabricated or re-emitted. |

Request preparation copies/freezes explicit history without freezing the application's arrays.
Current selection never changes history. Remote history accounting is **unknown server state**,
not zero. A future adapter must understand the specified remote-reference kind or reject it;
conversation, thread and previous-response IDs are not interchangeable.

`instructions` is a current contribution, separate from ordinary roles. Whether instructions should
replace, append to or persist on a server session is a future host/adapter policy. Similarly,
provider framing, tools, output schemas and asset limits are absent rather than guessed.

Most calls need one user message. When one invocation needs several newly authored messages,
`renderTurn({ input, beforeInput, afterInput, instructions })` emits `beforeInput → input → afterInput`.
Each entry carries a role and compiled prompt. Few-shot assistant examples can therefore be current
prompt material without masquerading as history. [Example 07](src/examples/07-current-messages.prompt.tsx)
shows this explicitly. No `Conversation` wrapper is required for the common case.

## Boundaries worth judging before the next architecture pass

This package selects our own JSX runtime through its own `tsconfig.json` and source exports.
The `*.prompt.tsx` extension communicates intent; by itself it does not route a compiler.
It has been exercised with `tsx`, TypeScript, Vitest, the private library build, and the Vite
browser playground. There is no mixed Solid/prompt file-routing plugin, installed-package test,
or source-capture transform yet. JSX `key` is accepted but ignored; explicit source labels are not
stable correspondence keys. Definition IDs are local to a compilation, and occurrence paths can
shift when sibling structure changes. Do not use them as cross-revision identities.

Output maps cover emitted code units and assets exactly, including generated Markdown syntax.
They map to owning occurrences, not precise input character spans. XML escapes are marked as
escaped; raw JSX whitespace cannot be reversed. No preview parser, scrolling, folding, output diff,
optimization algorithm, tokenizer, provider adapter or source navigation implementation is hidden
inside this bench. The independent viewer fixture tests those interaction expectations separately.
